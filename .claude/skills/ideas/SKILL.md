name: ideas
description: 콘텐츠 리서치. 외국인이 실제로 묻는 질문, 랭킹, 시즌 이슈를 조사해 근거 있는 아이디어를 시리즈별로 content/ideas.md에 쌓는다. "아이디어 찾아줘", "주제 리서치" 요청 시 사용.
---

1. `character/bible.md`, `content/series/*.md`(시리즈 포맷과 주제 기준), `content/ideas.md`, `content/hook-stats.md`, 최근 `content/reports/`를 읽는다.
2. **질문 수집기를 먼저 돌린다** (설명: `docs/reach.md`). 읽기 전용이라 승인 없이 돌려도 된다.
   ```
   python -m reach collect
   ```
   - 결과는 `content/research/<날짜>-questions.md`(후보 리포트)와 `<날짜>-raw.json`(원본)이다. 리포트의 수요 점수, 추천 훅, 근거 링크를 출발점으로 쓴다.
   - 리포트는 **후보**일 뿐이다. 근거 링크를 열어서 실제로 그 질문이 맞는지 확인한 것만 아이디어로 옮긴다. 시리즈·훅 추천이 어색하면 고친다.
   - 가져온 글이 없으면(네트워크 차단, 로그인 필요 등) 리포트의 "수집 기록" 오류를 사용자에게 알리고, 아래 웹 조사로만 진행한다. 결과를 지어내서 채우지 않는다.
   - Agent Reach 같은 다른 도구로 받아 둔 JSON이 있으면 `python -m reach analyze <파일>`로 같은 리포트를 만든다.
3. 웹에서 조사한다. **모든 아이디어에 근거 링크가 있어야 한다.**
   - 외국인 질문: 레딧 r/korea, r/koreatravel, r/AsianBeauty, r/KoreanBeauty 등에서 반복되는 질문
   - 랭킹·트렌드: 올리브영·다이소·편의점 랭킹과 신상, 한국 관련 해외 기사
   - 시즌: 다음 달의 명절, 행사, 여행 시즌, 블랙프라이데이 등
4. 시리즈별로 아이디어를 만든다 (월간 리서치는 시리즈 비율에 맞춰 총 40개 목표). 각각: 시리즈, 가제, 훅 템플릿 ID, 수요 근거 링크, 관련 상품(있으면), 시즌 날짜(있으면).
5. 점수(수요 1-5: 수집기 수요 점수를 참고 + 제휴 1-5 + 제작 쉬움 1-5 + 성과 보정 -2~+2)를 매겨 `content/ideas.md`에 `new`로 추가한다. 중복은 합치고, 근거가 약한 기존 항목은 `weak`로 표시한다.
6. 시리즈별 상위 아이디어를 요약해서 보여주고, 빼고 싶은 주제가 있는지 묻는다.
