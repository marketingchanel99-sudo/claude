# 레포 설명 카드 작성 가이드

목적: GitHub 레포 하나를 **중학생도 이해할 수 있게** 설명하는 2쪽짜리 PDF의 원고(JSON)를 쓴다.
PDF는 렌더러가 그림(흐름도, 아이콘, 전/후 비교, 난이도 게이지)과 함께 자동으로 만든다. 너는 JSON만 쓴다.

독자: 외국인 대상 "한국 생활템·문화" 숏폼(릴스·쇼츠·틱톡) 채널을 운영하는 1인 마케터.
코딩을 잘 모른다고 가정한다.

## 규칙
- 한국어, 존댓말 "~해요"체. 짧은 문장. 전문용어는 처음 나올 때 쉬운 말로 풀어 준다.
- **README에 있는 사실만** 쓴다. 가격, 성능 수치, 지원 플랫폼, 라이선스는 README에 있을 때만 쓴다. 모르면 쓰지 않는다. 추측 금지.
- README가 중국어면 영어 README(파일 뒤쪽에 이어 붙어 있음)도 참고하고, 내용을 한국어로 쓴다.
- 비유는 일상적인 것(레고, 택배, 통역사, 녹음기, 복사기, 비서 등)을 쓴다.
- 법·약관 위험(SNS 크롤링·다운로드·자동 상호작용·워터마크 제거·보이스 클론 등)이 있으면 `caution`에 꼭 쓴다.
- 글자 수 제한을 지킨다(레이아웃이 깨진다). 이모지는 쓰지 않는다(폰트에 없음).
- 파일 맨 앞의 README는 길 수 있다. 앞부분 300~400줄 정도와 목차 위주로 읽으면 충분하다. `head -n 400` 등을 활용한다.

## JSON 형식 (파일: content/<rank 3자리>.json, 예: content/001.json, UTF-8)
```json
{
  "rank": 1,
  "repo": "n8n-io/n8n",
  "name": "n8n",
  "one_liner": "앱들을 레고처럼 이어 붙여 반복 작업을 자동으로 돌리는 도구",   // 40자 이내
  "analogy": {
    "text": "도미노를 세워 두고 첫 번째만 건드리면 나머지가 알아서 넘어지는 것과 비슷해요.",  // 80자 이내
    "before": "매일 유튜브 확인하고, 시트에 적고, 메신저로 공유하기를 손으로 반복",   // 45자 이내, '이 도구가 없을 때'
    "after": "한 번 연결해 두면 새 영상이 뜰 때마다 자동으로 기록하고 알림"       // 45자 이내, '이 도구를 쓰면'
  },
  "what": [  // 3~4문장, 각 90자 이내. 무엇이고 무엇을 할 수 있는지
    "n8n은 여러 서비스(앱)를 선으로 연결해서 일을 자동으로 처리하게 만드는 프로그램이에요.",
    "..."
  ],
  "flow": [  // 작동 순서 그림. 3~5단계. label 8자 이내, desc 22자 이내
    {"label": "신호 받기", "desc": "새 영상이 올라오면 시작"},
    {"label": "정보 처리", "desc": "AI가 제목을 요약"},
    {"label": "결과 전달", "desc": "시트에 적고 알림 보내기"}
  ],
  "features": [  // 핵심 기능 3~4개. title 14자 이내, desc 45자 이내
    {"icon": "link", "title": "400개+ 앱 연결", "desc": "구글 시트, 슬랙 등과 바로 이어 붙여요"}
  ],
  "channel_use": [  // 우리 채널(외국인 대상 한국 생활템·문화 숏폼)에서 쓰는 구체적 장면 2~3개, 각 70자 이내
    "매일 아침 레딧에서 'Korea' 관련 인기 글을 모아 시트에 정리하기"
  ],
  "pros": ["...", "...", "..."],   // 2~3개, 각 35자 이내
  "cons": ["...", "...", "..."],   // 2~3개, 각 35자 이내
  "difficulty": 2,                 // 1(앱처럼 바로 사용) ~ 5(개발자+고성능 GPU 필요)
  "difficulty_note": "도커로 설치하거나 클라우드 버전 가입이 필요해요",   // 45자 이내
  "cost": "직접 설치하면 무료, 클라우드 버전은 유료",   // README 근거 있을 때만, 없으면 "오픈소스(무료 공개)" 또는 "README에 가격 정보 없음"
  "needs": ["컴퓨터 또는 서버", "도커(Docker)"],   // 준비물 2~4개, 각 20자 이내
  "glossary": [  // 이 문서에 나온 어려운 말 2~3개. term 12자 이내, meaning 45자 이내
    {"term": "노드", "meaning": "자동화 흐름 속 한 칸짜리 작업 상자"}
  ],
  "caution": "",                   // 약관·저작권·보안 주의(없으면 빈 문자열). 90자 이내
  "license": "README에 적힌 라이선스(예: MIT). 없으면 빈 문자열",
  "sources": ["README: 400+ integrations 문구", "README: self-host 가능 설명"]   // 근거 메모 2~4개
}
```

icon 값은 다음 중 하나만: video, mic, text, search, download, robot, clock, chart, globe, image, gear, upload, money, shield, bolt, link, code, chat, magic, eye

## 품질 체크

- channel_use가 실제 우리 채널(한국 생활템·문화를 외국인에게 소개하는 숏폼)에 맞는가?
- 숫자·가격·지원 범위가 README에 있는가?
- JSON이 `python3 -c "import json,sys;json.load(open(sys.argv[1]))" 파일`로 통과하는가?
