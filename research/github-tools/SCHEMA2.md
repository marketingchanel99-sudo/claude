# 레포 설명서 v2: 원리까지 담은 상세판

1차 원고(content/NNN.json)는 "너무 부실하다"는 피드백을 받았다. 이번에는 **같은 파일에 필드를 추가하고 기존 필드도 더 풍부하게 다듬어서** 4쪽 안팎의 상세 설명서로 만든다.
독자, 말투, 근거 규칙은 SCHEMA.md와 같다. 먼저 SCHEMA.md를 읽는다.
- 독자: 외국인 대상 "한국 생활템·문화" 숏폼 채널 운영자. 코딩은 잘 모르는 중학생 수준으로 생각한다.
- 말투: "~해요"체. 전문용어는 처음 나올 때 괄호로 풀이한다. 이모지는 쓰지 않는다.

## 근거 규칙 (중요)
- 레포 고유의 사실(기능, 지원 플랫폼, 설치 명령, 모델 이름, 수치, 가격, 라이선스)은 **README에 있는 것만** 쓴다.
- `principle`(원리)은 README에 나온 구조 설명을 우선 쓴다. README에 없으면 널리 알려진 기술의 **일반 원리**를 써도 된다. 예: 웹 크롤러가 HTML을 읽는 방식, TTS가 글자를 소리 조각으로 바꾸는 방식, 확산(diffusion) 모델이 노이즈를 걷어내며 이미지를 만드는 방식, 음성인식이 소리를 스펙트로그램(소리 그림)으로 바꿔 읽는 방식. 이 경우 sources에 "일반 원리: ..."라고 표시하고, 레포가 그렇게 한다고 단정하지 않는다("이런 도구는 보통 ~해요").
- 설치 명령(`cmd`)은 README에 나온 명령을 **글자 그대로** 옮긴다. 없으면 cmd를 비운다.
- 확실하지 않으면 쓰지 않는다.

## 추가·보강할 필드
```json
{
  "what": ["4~5문장. 기존보다 구체적으로: 무엇을 입력하면 무엇이 나오는지, 누가 왜 만들었는지"],
  "deep_dive": [  // 2~3문단, 각 120~220자. '이게 뭐예요?'보다 한 단계 깊게. 어떤 문제를 풀려고 만들었는지, 다른 방법과 무엇이 다른지
    "..."
  ],
  "principle": {
    "key_idea": "원리를 한 문장으로 (50자 이내). 예: 소리를 그림으로 바꾼 뒤, 그림 속 패턴을 글자로 번역해요",
    "analogy": "원리를 일상 비유로 (100자 이내)",
    "steps": [   // 속에서 일어나는 일 4~5단계. title 12자 이내, text 80~150자
      {"title": "소리 자르기", "text": "..."}
    ]
  },
  "architecture": {  // 구조도용 그림 데이터. 각 항목 14자 이내
    "inputs": ["유튜브 링크", "주제 키워드"],       // 1~3개
    "core": ["대본 생성(LLM)", "음성 합성(TTS)", "영상 합치기"],  // 2~4개, 처리 순서대로
    "outputs": ["완성 숏폼 mp4"]                       // 1~2개
  },
  "howto": [  // 따라 해 보기 4~6단계
    {"step": "설치하기", "detail": "무엇을 왜 하는지 60~120자", "cmd": "README에 있는 명령 그대로, 없으면 빈 문자열"}
  ],
  "scenario": {  // 우리 채널에 쓰는 구체적인 작업 흐름 하나 (channel_use보다 자세히)
    "title": "예: '한국 편의점 신상' 쇼츠 대본용 레퍼런스 모으기",
    "steps": ["1단계 설명(70자 이내)", "...", "4~6단계"]
  },
  "compare": [  // repos.tsv에서 비슷한 레포 2~3개를 골라 차이를 쓴다. 비교 대상 레포의 README도 읽어 확인한다
    {"name": "Whisper", "rank": 7, "diff": "차이점 80자 이내"}
  ],
  "faq": [  // 초보가 실제로 궁금해할 질문 3개. a는 120자 이내, README 근거
    {"q": "한국어도 되나요?", "a": "..."}
  ],
  "images": [  // images/<owner>_<repo>.json에 후보가 있을 때만. Read 도구로 이미지를 직접 보고, 내용을 설명해 주는 이미지 최대 2개를 고른다(로고·광고·사람 사진·의미 없는 배너 제외)
    {"file": "images/owner_repo_1.jpg", "caption": "이미지 속 화면이 무엇인지 60자 이내"}
  ]
}
```
기존 필드(one_liner, analogy, flow, features, channel_use, pros, cons, difficulty, cost, needs, glossary, caution, license, sources)는 유지하고, 더 정확하게 고칠 것이 있으면 고친다. glossary는 이번에 3~5개로 늘린다. sources에는 새로 쓴 내용의 근거를 추가한다(2~6개).

## 검증
- `python3 -c "import json,sys;json.load(open(sys.argv[1]))" 파일`이 통과해야 한다.
- images의 file 경로는 실제로 있는 파일이어야 한다.
