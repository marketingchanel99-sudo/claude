# Trend Radar 설계서 (초안, 승인 전)

> 여러 분야에 공통으로 쓰는 **트렌드·영상 분석 시스템**. 분야는 설정 파일 하나로 바꾼다.
> [Agent Reach](https://github.com/Panniantong/Agent-Reach)의 구조(플랫폼마다 도구를 순서대로 시도, 결과 모양 통일, 읽기 전용)를 빌려 오되, 수집 경로는 **공식 API를 먼저** 쓴다.
> 이 문서가 승인되면 1단계(유튜브)부터 만든다.

## 1. 하는 일 세 가지

| 기능 | 질문에 답한다 | 결과물 |
|---|---|---|
| **A. 뜨는 주제·키워드** | 이 분야에서 지금 뭐가 뜨나? 지난주보다 뭐가 커졌나? | 주간 트렌드 리포트: 급상승 키워드·해시태그·사운드, 대표 영상 |
| **B. 잘 된 영상 뜯어보기** | 이 영상은 왜 잘 됐나? 훅, 구성, 길이, 말투는? | 영상별 분석 카드 + 분야별 "잘 되는 패턴" 요약 |
| **C. 벤치마킹 채널 추적** | 경쟁 채널이 이번 주에 뭘 올렸고, 뭐가 평소보다 잘 됐나? | 채널별 새 영상과 이상치(평소 대비 몇 배) 알림 |

세 기능은 따로 노는 게 아니라 한 줄로 이어진다: **C에서 수집 → A에서 이상치·급상승을 고름 → B에서 뜯어봄**.

## 2. 전체 구조

```
 niches/<분야>.yaml  ── 키워드, 해시태그, 벤치마킹 채널, 지역·언어, 플랫폼
        │
        ▼
 ┌──────────── 수집 (collectors) ─────────────┐
 │ youtube   tiktok   instagram                │  플랫폼마다 백엔드를 순서대로 시도
 │ (공식 API → yt-dlp → Agent Reach)          │  결과는 Video / Channel 한 모양으로
 └─────────────────────┬──────────────────────┘
                       ▼
 ┌──────── 저장 (SQLite: data/radar.db) ──────┐
 │ videos · channels · snapshots(시점별 조회수) │  같은 영상을 여러 번 찍어 둬야
 │ analyses(영상 분석 결과)                     │  "속도"와 "증가"를 계산할 수 있다
 └─────────────────────┬──────────────────────┘
                       ▼
 ┌──────────── 분석 (analyzers) ──────────────┐
 │ trend:   키워드·해시태그 빈도와 증가율       │
 │ outlier: 채널 평소 대비 몇 배, 시간당 조회수 │
 │ teardown: 다운로드 → 받아쓰기 → 장면 분할   │
 │           → 첫 3초 프레임 → 구조 분석       │
 └─────────────────────┬──────────────────────┘
                       ▼
 reports/<분야>/<날짜>-trends.md · -teardown.md · -benchmarks.md
```

## 3. 분야 설정 (여러 분야 적용의 핵심)

분야를 추가하는 일 = 설정 파일 하나를 쓰는 일. 코드는 안 바뀐다.

```yaml
# niches/kbeauty.yaml (예시)
name: K-뷰티
language: en          # 분석할 영상 언어
regions: [US, GB]     # 유튜브 인기 차트·검색 지역
platforms: [youtube, tiktok, instagram]
keywords:             # 검색어 (트렌드 A)
  - korean skincare
  - olive young haul
hashtags: [kbeauty, oliveyoung, koreanskincare]   # 틱톡·인스타 (트렌드 A)
benchmarks:           # 추적할 채널 (C)
  youtube: ["@채널핸들1", "@채널핸들2"]
  tiktok: ["@계정1"]
  instagram: ["계정1"]
formats: [shorts, long]   # 롱폼 포함 여부
teardown:
  per_week: 10        # 주당 뜯어볼 영상 수 (비용·시간 상한)
```

## 4. 플랫폼별 수집 경로 (현실적인 가능 범위)

플랫폼마다 열려 있는 정도가 다르다. **공식 경로 → 공개 도구 → 로그인 브라우저(Agent Reach)** 순서로 시도한다.

| | 검색·트렌드 (A) | 채널 추적 (C) | 영상 파일·자막 (B) | 필요한 것 |
|---|---|---|---|---|
| **YouTube 롱폼·Shorts** | ✅ Data API v3 검색(기간·지역 지정), 지역별 인기 차트 | ✅ 채널 업로드 목록 + 조회·좋아요·댓글 수 | ✅ yt-dlp (자막, 다운로드) | API 키 (무료, 하루 할당량 있음) |
| **Instagram Reels** | 🟡 Graph API 해시태그 검색 (인기·최신 게시물, 7일에 해시태그 30개까지) | 🟡 Graph API Business Discovery: **비즈니스·크리에이터 계정만** 게시물과 반응 수 조회 | 🟡 yt-dlp (링크 단위, 자주 막힘) | 우리 인스타 크리에이터 계정 + Meta 앱 토큰 (업로드용으로 이미 준비 예정) |
| **TikTok** | 🟡 Creative Center 공개 트렌드(해시태그·사운드·영상), Higgsfield `tiktok_music_trending`(인기 사운드) | 🔴 공식 API로는 남의 계정 조회 불가. yt-dlp 계정 페이지(불안정) 또는 Agent Reach 브라우저 | 🟡 yt-dlp (링크 단위) | 일부는 브라우저 로그인(부계정) |

- ✅ 안정적, 🟡 제한적, 🔴 공식 경로 없음.

**원칙: 공식 API로 되는 건 공식 API, 안 되는 것만 다른 도구.** 공식 API에 아예 없는 기능이 있어서 공식 API만으로는 다 할 수 없다.

| 필요한 것 | 공식 API로 되나 | 그래서 쓰는 것 |
|---|---|---|
| 유튜브 조회수·좋아요·댓글 수, 검색, 채널 영상 목록 | ✅ Data API v3 | 공식 API |
| 남의 유튜브 영상 자막 | ❌ 자막 다운로드(`captions.download`)는 영상 주인 권한이 필요 | yt-dlp |
| 영상 파일 (장면 분할·프레임용) | ❌ 어느 플랫폼도 남의 영상 파일을 주지 않음 | yt-dlp |
| 인스타 남의 계정 | 🟡 비즈니스·크리에이터 계정만 (Business Discovery). 개인 계정용 Basic Display API는 2024년 12월 종료 | Graph API, 안 되면 브라우저 |
| 틱톡 남의 계정·검색 | ❌ 일반 개발자용 없음 (Research API는 학술 연구자 대상) | 공개 트렌드 페이지, yt-dlp, 브라우저 |
- **유튜브가 가장 확실하다.** 그래서 1단계는 유튜브로 세 기능을 모두 완성하고, 인스타·틱톡은 같은 틀에 백엔드만 추가한다.
- Shorts와 롱폼은 길이로 나눈다. Shorts는 최대 3분이라서 3분 이하는 `shorts`로 보되, 세로 비율도 함께 확인한다.
- 스크래핑 경로(yt-dlp 계정 페이지, 브라우저)는 플랫폼 약관상 회색 지대다. **부계정만** 쓰고, 요청 간격을 두고, 막히면 멈춘다(재시도 폭주 금지).
- 위 API 한도와 권한 범위는 구현 전에 공식 문서로 다시 확인한다 (특히 Business Discovery로 릴스 **조회수**가 오는지는 확인 필요).

## 5. 핵심 지표 (분석 로직)

| 지표 | 계산 | 쓰는 곳 |
|---|---|---|
| **시간당 조회수** | 조회수 ÷ 게시 후 경과 시간 | A, C. 오래된 영상과 새 영상을 공정하게 비교 |
| **이상치 점수** | 이 영상 조회수 ÷ 그 채널 최근 30개 영상 조회수 중앙값 | C. "평소보다 5배" = 주제나 훅이 먹혔다는 신호 |
| **반응률** | (좋아요 + 댓글) ÷ 조회수 | A, C. 조회수만 높고 반응 없는 영상 걸러내기 |
| **키워드 증가율** | 이번 주 상위 영상 제목·태그 속 키워드 빈도 ÷ 지난 4주 평균 | A. 급상승 키워드 |
| **조회수 증가 속도** | 스냅샷 두 시점 사이 조회수 차이 ÷ 시간 | A, C. 지금 뜨고 있는 영상 |

- 숫자는 모두 **수집한 값으로만** 계산한다. 값이 없으면(예: 비공개 좋아요) 빈칸으로 두고 추정하지 않는다.
- 이상치 점수와 증가율은 스냅샷이 쌓여야 의미가 생긴다. 첫 2~3주는 "기준선 쌓는 중"으로 표시한다.

## 6. 영상 뜯어보기 (B) 상세

```
링크 → 다운로드(yt-dlp, 720p 이하) → ① 자막/받아쓰기 → ② 장면 분할 → ③ 핵심 프레임 → ④ 구조 분석 → 분석 카드
```

| 단계 | 방법 | 비용 |
|---|---|---|
| ① 대본 | 유튜브 자막이 있으면 그대로. 없으면 음성 받아쓰기 (로컬 Whisper 또는 Groq API) | 로컬은 무료, Groq는 키 필요 |
| ② 장면 분할 | ffmpeg 장면 변화 감지 → 컷 수, 컷 평균 길이, 첫 컷 길이 | 무료 |
| ③ 핵심 프레임 | 0초·1초·2초·3초 + 각 장면 첫 프레임 이미지 | 무료 |
| ④ 구조 분석 | Claude가 대본 + 프레임을 보고 정리: 훅 유형(`content/hooks.md` ID에 맞춤), 첫 문장, 화면 첫 동작, 자막 유무, 구성(문제→해결, 랭킹, 비교…), CTA, 길이 | 세션 안에서 처리 |
| (선택) | Higgsfield `video_analysis_create`, `virality_predictor` | **크레딧이 들 수 있음** → 매번 비용 확인 후 승인 (`content/budget.md` 규칙) |

분석 카드는 JSON(`analyses` 테이블)과 md 둘 다 남긴다. 10개 이상 쌓이면 분야별로 "잘 되는 패턴"을 요약한다: 자주 쓰는 훅, 평균 길이, 컷 속도, 첫 문장 길이.

## 7. 실행 방법 (예정)

```bash
python -m radar collect kbeauty          # 수집 + 스냅샷 저장
python -m radar trends kbeauty           # A 리포트
python -m radar benchmarks kbeauty       # C 리포트 (이상치 알림)
python -m radar teardown <영상 링크>     # B 한 개
python -m radar teardown kbeauty --top 10   # 이번 주 이상치 상위 10개 자동 분석
```

- 주기 실행: 하루 1번 `collect`, 주 1번 리포트. 사용자 PC의 작업 스케줄러 또는 클라우드 예약 작업.
- 채널 운영 흐름과의 연결: 이 채널(Jiwoo)에서는 `docs/WORKFLOW.md`의 **시장 조사(벤치마킹 계정 10개, 레퍼런스 릴스 30개)**와 `/ideas` 리서치의 근거로 쓴다. 다른 분야는 같은 도구에 설정 파일만 추가한다.

## 8. 만드는 순서

| 단계 | 범위 | 끝났다는 기준 |
|---|---|---|
| **1. 유튜브 MVP** | 분야 설정, SQLite 저장, Data API 수집(검색·차트·채널), 지표 5개, A·C 리포트 | 실제 분야 1개로 리포트 2주치 |
| **2. 영상 뜯어보기** | yt-dlp 다운로드, 자막·받아쓰기, ffmpeg 장면 분할, 프레임, 분석 카드, 패턴 요약 | 영상 10개 분석 카드 |
| **3. 인스타그램** | Graph API 해시태그·Business Discovery 백엔드, 릴스 링크 다운로드 | 벤치마킹 계정 10개 추적 |
| **4. 틱톡** | Creative Center 트렌드, 인기 사운드, 링크 단위 분석, (선택) 브라우저 백엔드 | 해시태그 트렌드 리포트 |
| **5. 대시보드 (선택)** | 리포트를 웹 페이지로 (분야별 탭, 그래프) | - |

## 9. 결정이 필요한 것 (사용자)

1. **첫 분야:** 1단계를 시험할 분야 1개와 벤치마킹 채널 몇 개.
2. **유튜브 API 키:** Google Cloud에서 YouTube Data API v3 키 발급 (업로드용 OAuth와 별개, 무료).
3. **실행 장소:** 사용자 PC(권장, 막힘이 적음) 또는 클라우드(네트워크 허용 목록에 `www.googleapis.com`, `www.youtube.com`, `graph.facebook.com` 등 추가 필요).
4. **받아쓰기:** 로컬 Whisper(무료, PC 사양 필요) 또는 Groq 키.
5. **틱톡·인스타 브라우저 경로:** 부계정 로그인을 쓸지 여부.
